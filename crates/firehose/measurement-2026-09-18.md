# Brief 08 measurement and acceptance report — 2026-09-18

## Conditions

- Local macOS arm64 host, APFS-backed `/tmp`; Rust **debug** build, per-block
  file fsync and directory fsync, no subscribers. Workspace builds/tests ran
  concurrently for portions of these measurements. These are smoke measurements,
  not a saturated or isolated performance benchmark.
- hog-devnode **0.1.28-rc.1**, commit
  `d54945959a6a089e95e1337404ea71e5fcdc544c`, protocol
  `hogp/63c9284d8d5727e`; existing workspace Rust protocol bindings **0.36.0**.
- Node flags: `--ramdb-bytes 268435456 --dev-accounts 2`, default public
  development-account seed and dev-wallet profile, fresh persistent data dir.
- Driver: `examples/drive_blocks.rs`, mirroring node-supervisor's manual
  scheduler proposal/commit sequence and proposal compatibility hash. It waits
  for archive file visibility, then sleeps 250 ms. Actual intervals are about
  265–275 ms, including proposal, commit and archive work. It uses the supervisor's
  zero proposal timepoint, so measurements use host monotonic clocks rather than
  interpreting header timepoints as wall time.
- Traffic: one bootstrap transaction emitting five events; otherwise empty
  blocks, plus separate batches of **100** and **1,000** signed dev-wallet
  self-calls generated by `examples/submit_traffic.rs`, nonce starts 100000 and
  200000. The self-calls commit with **zero emitted events**; these are the
  workspace benchmark's self-call shape, not successful application traffic or
  a 10,589-event workload.

## Byte sizes

Values are exact serialized bytes, including each batch's four-byte vector
length. Archive files additionally include the 68-byte origin and 32-byte
consensus identity; payload includes a four-byte format version.

| Block shape | N sampled | ConsensusValue | Event-log batch | Transaction-body batch | Full payload | Archive record |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Bootstrap, 1 tx / 5 emitted events | 1 | 288 | 608 | 7,624 | 8,524 | 8,624 |
| Empty | 115 | 288 | 4 | 4 | 300 | 400 |
| 100 self-calls / 0 emitted events | 1 | 288 | 4,404 | 22,804 | 27,500 | 27,600 |
| 1,000 self-calls / 0 emitted events | 1 | 288 | 44,004 | 228,004 | 272,300 | 272,400 |

**The design's 508-byte hogd committed record is confirmed:** all 118
`committed-*.outbox` files were exactly 508 bytes. That includes hogd's envelope;
the `ConsensusValue` XDR itself is 288 bytes. They are different measurements.

hogd's four distinct content-addressed `.events` files measured **0, 8,224,
27,200 and 272,000 bytes**. Those files hold event logs **and transaction
bodies**, without the two XDR batch-length prefixes. The 1,000-call event-log
batch alone is about 44 KB, but its `.events` file is 272 KB. The design's
~1.3 KB typical payload and ~2 KB/block estimate are **not established for this
traffic**. Omitting transaction bodies substantially understates raw archive
growth for the tested nonempty blocks.

## Live following, lag and throughput

Arrival measurement starts immediately before the commit RPC and ends when
the height file appears, checked at approximately 1 ms intervals. Publication
is inside that interval, so these are conservative upper bounds on publication
to file visibility. Visibility can precede directory fsync; tail output and
cursor advancement occur only after that fsync.

| Run | Blocks | Median arrival | Maximum arrival | Result |
| --- | ---: | ---: | ---: | --- |
| Empty live-follow batch | 30 | 12.37 ms | 13.99 ms | All archived |
| 100-call block plus four empty blocks | 5 | 10.79 ms | 13.39 ms | All archived |
| 1,000-call block plus one empty block | 2 | 33.25 ms | 55.87 ms | All archived |

All normal following arrivals were below the driver's 250 ms sleep interval.
The 1,000-call block itself took 55.87 ms; its following empty block took
10.63 ms. Live empty-block ingestion followed the driver at roughly 3.7
blocks/s; this is an offered-rate observation, not maximum service capacity.

During the restart/follow run, the independent scheduler tip sampler ran every
250 ms and the observer scraped metrics about every 25 ms: **703 observations**,
**671 at lag 0**, **32 at lag 1**. No observed lag exceeded one block after
health returned. Sampling does not establish an instantaneous maximum. No tip
height can be derived from procedure 10 itself.

A fresh archive replayed heights 1–116 in **1.04245 s**, including process
startup and per-block sync: **111.28 blocks/s**, **78,492 logical archive
bytes/s**. This corpus is one bootstrap block, one 100-call block and 114 empty
blocks (81,824 bytes total); small-file sync dominates. It is not a large-block
throughput benchmark.

## Storage growth

Allocation uses `st_blocks * 512` on this filesystem, excluding directory
metadata, lock and temporary files. Logical sizes count full archive records.
The extrapolations repeat the measured traffic mix; they are not chain-growth
forecasts. MB here means 1,000,000 bytes.

| Corpus | Logical bytes | Allocated bytes | Logical / 100k blocks | Allocated / 100k blocks |
| --- | ---: | ---: | ---: | ---: |
| First 116 blocks, before the 1,000-call batch | 81,824 | 507,904 | 70.54 MB | 437.85 MB |
| Final 118 blocks | 354,624 | 786,432 | 300.53 MB | 666.47 MB |
| Empty blocks alone | 400/block | 4,096/block | 40 MB | 409.6 MB |

The one-file-per-height choice is deliberately simple but cannot claim its
logical size as its disk usage. Segment packing is a justified future
optimisation once file count, allocation or startup scan time matters.

## Restart and corruption

- An 80-block driver run continued while the firehose was SIGKILLed and
  restarted. The killed process had **37 durable blocks**. Recovery reported
  **45.57 ms** of archive verification and resumed by writing height **38**.
- Observed process-spawn to HTTP 200 was **820 ms**, including startup/scheduling
  and observer overhead under concurrent workspace tests. The deliberately
  interrupted block took **942.65 ms** from commit request to archive, exceeding
  normal block time during the outage; no zero-downtime claim is made.
- The archive ended contiguous at height **116**, with exactly **116 files**
  and no duplicate heights. The restarted process counted 79 new blocks.
  Both the driver and subsequent graceful service shutdown exited zero.
- A separate cold-process `verify` on those 116 blocks took **117.89 ms**
  externally, **93.42 ms** inside recovery. “Cold” means a new process; the OS
  page cache was warm and was not flushed.
- A copied archive with a flipped byte in height 1's event-log transaction hash
  failed recovery with exit 1: `transaction body hash mismatch`. Automated tests
  separately corrupt emitted events, transaction bodies, `txs_hash`, and
  consensus identity; verify gap/epoch/rewrite rejection; and cover partial
  writes and a crash leaving `pending` hard-linked to a published record.

## Discovery and design differences

Discovery probed all **19** listeners belonging to this test node. Exactly one
matched `EventIndexer1`; the other 18 were clean negatives. No event endpoint
was present in readiness's runtime manifest. No supervisor schema change was
made. The number of internal listeners is version/topology dependent; this
node has more than the twelve observed in the brief.

Corrections or explicit departures from the parent checkout's
`plan/event-firehose-2026-09-18.md`:

1. There is no standalone EventIndexer intro RPC. Discovery uses the
   non-parking uninitialized procedure-10 request, which carries the token.
2. The existing workspace is on 0.36.0, with a request-only `CaughtUp` state;
   a plain `Initialized` cursor returns promptly at the tip. Correct parking
   requires the explicit transition after `PullCaughtUp`.
3. Lag requires an independently sampled tip endpoint; procedure 10 supplies
   no tip height. Unknown lag is NaN, never an assumed zero.
4. The 508-byte node record is confirmed, but that is not `ConsensusValue` XDR
   size. `.events` contains transaction bodies as well as logs; the raw archive
   can be substantially larger than the note's small-payload estimate.
5. The experimental store uses immutable height files containing content
   commitments, rather than a separate content-addressed blob layer and index.
   Filesystem allocation and O(N) recovery are documented tradeoffs.
6. On this fresh node, the oldest outbox block is height 1 (bootstrap). The
   archive starts at the advertised origin, not an invented height-0 record.
